# 00 导读：学习地图与三遍读法

## 本课目标

- 知道 1450 行分布在哪些文件、为什么这几个文件是"主干"，哪些是"零件"；
- 选出适合自己的一条阅读路线，不要从 `qwen3.py` 第一行开始读；
- 知道哪些结论本机能验证（跑 `labs/`）、哪些必须靠读码（kernel、CUDA Graph）。

一个容易被目录骗的地方：`model_runner.py` 是最大的文件，但它的 257 行里真正"难"的只有 `allocate_kv_cache`（19 行）和 `capture_cudagraph`（35 行）；剩下 200 行是"把 Python 列表变成 pinned tensor"的搬运工。读的时候可以直接跳到这两段。

## 2. 三条路线

### 路线 A：引擎读者（默认，约 12 小时）

```
00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 13 → 14
```
先建立"一次 step 的完整调用链"，再看调度与缓存，最后看 GPU 侧。**不理解 04/05 的话，09 里的 slot_mapping 会莫名其妙。**

### 路线 B：性能/系统读者（约 8 小时）

```
00 → 01 → 08 → 04 → 05 → 13 → 09 → 14
```
关心"为什么快"：显存怎么算、图怎么捕、注意力怎么读分页缓存。跳过模型细节。

### 路线 C：面试/汇报（约 4 小时）

```
00 → 01 → 02 → 04 → 05 → 12 → 14 → 15
```
一条主线：请求 → 调度 → 缓存 → 采样 → 基准 → 与生产框架对比。

## 3. 三遍读法

1. **第一遍（不看代码）**：读 `docs/01`、`docs/02`，在纸上画出"prompt 进来 → 出 token"的链路。画不出来就别往下走。
2. **第二遍（对着代码）**：每节课都带 `文件:行号`，在编辑器里逐段打开，改一个变量看看谁在用（`num_scheduled_tokens` 值得追一遍，它是全项目最被滥用的字段）。
3. **第三遍（动手）**：跑 `labs/`，然后自己改：把 `max_num_batched_tokens` 调到 8 观察分块；把 `num_kvcache_blocks` 调到 4 观察抢占；把 `temperature` 调成 0 看它 assert 你。

## 4. 本机能验证什么、不能验证什么

先摆事实（本机实测）：

```
$ sysctl -n machdep.cpu.brand_string   →  Apple M5
$ python3 -c "import torch"            →  ModuleNotFoundError
$ pyproject.toml requires-python       →  ">=3.10,<3.13"（本机 3.14.7）
```

三条硬门槛：`flash-attn` 与 `triton` 需要 CUDA 工具链；`dist.init_process_group("nccl")` 硬编码 NCCL（`model_runner.py:26`）；Python 版本超出声明范围。**所以端到端推理在本机跑不起来。**

但引擎逻辑不碰 CUDA，可以原样跑：

| 能验证（已跑，见 `labs/RUN_OUTPUT.md`） | 只能静态分析 |
| --- | --- |
| `BlockManager` 的分配、哈希链、尾块不共享 | Triton `store_kvcache_kernel` 是否高效 |
| `Scheduler` 的 prefill 优先、chunk 只给队首、LIFO 抢占 | CUDA Graph 捕获/复用的正确性 |
| `Sequence` 的序列化瘦身 | FlashAttention 的 varlen / paged 行为 |
| Gumbel-max 采样（numpy 等价复现） | 端到端 tok/s、显存占用 |

`labs/sim_prefix_cache.py` 和 `labs/sim_scheduler.py` 直接 `import nanovllm.engine.*` —— 只把 `nanovllm.config` 换成空壳以绕开 transformers/torch。你看到的每一条结论都来自真实执行，不是复述注释。

## 5. 术语表（后文不再解释）

| 术语 | 在本项目里的具体含义 |
| --- | --- |
| block / 块 | KV cache 的分配单位，默认 256 token（`config.py:17`，且 assert 必须是 256 的整数倍） |
| block_table | 一条序列的"逻辑块号 → 物理块号"映射，`sequence.py:28` |
| slot | 物理 KV 张量里的一个 token 位置，`slot = block_id * block_size + offset` |
| prefill | 一次算完（或分块算）整段 prompt |
| decode | 每步每序列算 1 个 token |
| varlen | FlashAttention 的变长批接口，用 `cu_seqlens` 描述每段长度 |
| step | `LLMEngine.step()` 一次，等于一次前向 + 一次后处理 |
| ref_count | 一个物理块被多少条序列共享（前缀缓存的结果） |
| 抢占 preempt | KV 不够时把某条正在 decode 的序列清空，退回 waiting |
| eager / graph | 直接跑 vs 用捕获的 CUDA Graph 重放 |
