# 01 项目全景与血统

## 本课目标

- 一句话说清 nano-vllm 是什么、不是什么；
- 把它和 vLLM 的组件一一对上号（这样读 vLLM 源码时能直接迁移）；
- 用 grep 计数证明"它没有 X"，而不是凭印象猜；
- 记住六个边界，避免拿它当生产引擎用。

## 1. 它是什么

README 第一句：*A lightweight vLLM implementation built from scratch.*（`README.md:11`）

- **一个离线批推理引擎**：入口是 `LLM.generate(prompts, sampling_params)`，同步阻塞，返回列表。
- **只为 Qwen3 服务**：`models/` 下只有 `qwen3.py`，`model_runner.py:9` 里 `from nanovllm.models.qwen3 import Qwen3ForCausalLM` 是硬编码，没有模型注册表（grep `registry` → 0）。
- **教学尺度的"骨架完整"**：分页 KV、前缀缓存、连续批处理、张量并行、CUDA Graph、FlashAttention 一样不缺。
- **性能与 vLLM 同档**：README 给的实测是 1434 vs 1362 tok/s（`README.md:58-61`），详见 `docs/14`。

## 2. 它不是什么（用 grep 计数说话）

在 `nanovllm/`、`bench.py`、`example.py` 上跑 `grep -rn -i <pattern> | wc -l`：

| 能力 | 命中数 | 结论 |
| --- | ---: | --- |
| `top_k` / `top_p` | 0 / 0 | 只有纯温度采样，没有截断采样 |
| `repetition_penalty` | 0 | 没有重复惩罚 |
| `logprobs` | 0 | 不返回对数概率 |
| `stop_token_out` / 停止串 | 0 | 只按 `eos_token_id` 和 `max_tokens` 停 |
| `stream` | 0 | 没有流式输出，`generate` 一次性返回 |
| `FastAPI` / `HTTP` | 0 / 0 | 没有 OpenAI 兼容服务端（vLLM 有，这里没有） |
| `swap` / `offload` | 0 / 0 | KV 不够就抢占重算，不换出到 CPU |
| `fp8` / `int8` / `quant` | 0 / 0 / 0 | 没有量化，一律用模型原始 dtype |
| `sliding_window` / `sink` | 0 / 0 | 没有滑窗注意力、没有 attention sink |
| `beam` | 0 | 没有 beam search |
| `LoRA` | 0 | 没有适配器 |
| `specul` | 0 | 没有投机解码（对照 DeepInfer 的 DSpark） |
| `seed` | 2 | 只出现在 `bench.py` 的 `random.seed(0)`，引擎层不能指定采样种子 |

`seed=2` 这条值得展开：采样只用 `torch` 默认 RNG，`SamplingParams` 里没有种子字段（`sampling_params.py:5-8`），所以**同一 prompt 跑两次结果不同，且不可复现**。这不是 bug，是"最小实现"的自觉取舍。

## 3. 血统：和 vLLM 的组件对照

| vLLM 里的名字 | nano-vllm 里的对应物 | 差异 |
| --- | --- | --- |
| `LLMEngine` + `EngineCore` | `engine/llm_engine.py`（90 行） | 没有多进程前端/后端分离，全在一个进程里同步跑 |
| `Scheduler` | `engine/scheduler.py`（92 行） | 只有 waiting/running 两队列，没有 swapped 队列，没有 token 级插空 |
| `BlockSpaceManager` / `KVCacheManager` | `engine/block_manager.py`（120 行） | 只有 hash 前缀缓存，没有 LRU 淘汰、没有 waterfall 分配 |
| `SequenceGroup` / `SequenceData` | `engine/sequence.py`（83 行） | 没有 beam/并行样本组，一条 Sequence 就是一条请求 |
| `ModelRunner` | `engine/model_runner.py`（257 行） | 只有 rank0 采样，没有 PP/EP |
| PagedAttention kernel | `layers/attention.py` 的 `store_kvcache_kernel` + FlashAttention | 用 Triton 写 KV + 调用 FlashAttention，不自己写 attention kernel |
| `LinearMethod` / tensor parallel layers | `layers/linear.py`（156 行） | 只保留列并行/行并行/QKV 合并三种，无量化分支 |
| `InputBatch` / `CUDAGraphRunner` | `model_runner.py` 的 `prepare_*` + `capture_cudagraph` | 图按 batch size 分桶捕获，pool 共享 |
| OpenAI server / metrics | 无 | 明确不做 |

**一句话血统**：它不是 vLLM 的 fork，实现是重写的，但概念一一对应 —— 这正是它最有价值的地方：**你在这里读懂的每个函数，在 vLLM 里都有一个同名近亲，只是包了十层。**

## 4. 依赖栈与运行门槛

`pyproject.toml:14-20`：

```
torch>=2.4.0    triton>=3.0.0    transformers>=4.51.0    flash-attn    xxhash
requires-python = ">=3.10,<3.13"
```

关键在最后一行和 `flash-attn`：**没有 CUDA 就没有 attention，没有 attention 就没有引擎**。另外 `model_runner.py:26` 把 NCCL 和地址写死：

```python
dist.init_process_group("nccl", "tcp://localhost:2333", world_size=self.world_size, rank=rank)
```

`tcp://localhost:2333` 是硬编码端口 —— 同一台机器起两个 `LLM` 实例（或多卡多实例）会撞端口。这是教学实现的典型取舍：省掉一个 `--master-port` 参数。

## 5. 六个边界（记住这几条，别用错）

1. **单机单模型**：没有模型注册表，`Qwen3ForCausalLM` 写死；换模型要改代码。
2. **只有 TP，没有 EP/DP/PP**：`tensor_parallel_size` 1–8（`config.py:23`），进程数 = 卡数，一卡一份全量模型。DeepInfer 恰好相反（只做 EP/DP，没有 TP），见 `docs/15`。
3. **只能离线批处理**：`generate` 同步阻塞，没有流式、没有服务端、没有请求取消。
4. **调度粒度是"批"**：一次 step 全 prefill 或全 decode，prefill 期间 decode 饿死（`labs/sim_scheduler.py` case1 已实测）。
5. **KV 不可换出**：`swap`/`offload` 命中 0，抢占了就重算。
6. **采样只有温度**：没有 top-k/top-p/惩罚/种子，且**禁止 temperature=0**（`sampling_params.py:11`）。

## 7. 设计取舍：为什么能压到 1450 行

| 舍弃 | 换来的 | 代价 |
| --- | --- | --- |
| 模型注册表 | 直接 new `Qwen3ForCausalLM` | 换模型要改 `model_runner.py:9` |
| 多进程前后端分离 | 一个进程里同步跑 | 无法在生成中插入新请求、无流式 |
| 混合批（prefill+decode 同批） | 调度器 92 行搞定 | decode 在 prefill 期间饥饿 |
| KV swap / 淘汰 | 块管理器 120 行搞定 | 抢占了全量重算 |
| 量化 / 投机 / 滑窗 | 注意力 75 行搞定 | 只适合小模型 + 短上下文 |
| 采样族 | 采样器 12 行 | 只有温度可用 |
