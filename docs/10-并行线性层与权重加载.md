# 10 并行线性层与权重加载

## 本课目标

- 分清列并行与行并行的切法、通信点、以及"bias 只在 rank0 加"这个优化；
- 看懂 `QKVParallelLinear` 为什么不能简单 `chunk`；
- 弄明白 `weight_loader` 为什么挂在 `Parameter` 上而不是模块上；
- 知道 `packed_modules_mapping` 的 `for...else` 是怎么决定"合并加载"还是"普通加载"的。

## 1. 四种线性层，一张表

| 类 | 切什么 | forward 里有通信吗 | 用在 |
| --- | --- | --- | --- |
| `ReplicatedLinear` | 不切 | 无 | 本模型未用（保留） |
| `ColumnParallelLinear` | 输出维（`tp_dim=0`） | 无 | 一般列并行 |
| `MergedColumnParallelLinear` | 输出维，**按 shard 分段** | 无 | `gate_up_proj` |
| `QKVParallelLinear` | 输出维，**q/k/v 三段各自偏移** | 无 | `qkv_proj` |
| `RowParallelLinear` | 输入维（`tp_dim=1`） | `all_reduce` | `o_proj`、`down_proj` |

记忆法：**列并行"切输出"，各卡算自己那部分，不通信；行并行"切输入"，各卡算部分和，必须 `all_reduce` 求和。**

```
列并行:  x[1×d] ──▶ W[d×o/2] ──▶ y[o/2]     （每卡一段输出，结果不完整）
行并行:  x[1×d/2] ─▶ W[d/2×o] ─▶ y_part[o]   → all_reduce → y[o]（完整）
```

## 2. `LinearBase`：把 loader 挂到参数上

```python
# linear.py:12-31
class LinearBase(nn.Module):
    def __init__(self, input_size, output_size, bias=False, tp_dim=None):
        self.tp_dim = tp_dim
        self.tp_rank = dist.get_rank()
        self.tp_size = dist.get_world_size()
        self.weight = nn.Parameter(torch.empty(output_size, input_size))
        self.weight.weight_loader = self.weight_loader      # ← 挂函数到 Parameter
        if bias:
            self.bias = nn.Parameter(torch.empty(output_size))
            self.bias.weight_loader = self.weight_loader
```

**为什么挂在 `Parameter` 上**：加载器（`utils/loader.py`）遍历的是"safetensors 里的权重名"，它只能通过 `model.get_parameter(name)` 拿到 `Parameter`，拿不到"这个参数属于哪个模块"。把 `weight_loader` 挂成参数属性，就等于给每个参数附加了一句"我该怎么被填"。

这是 vLLM 的经典做法，也是这个项目"血统"最明显的地方之一（vLLM 里叫 `default_weight_loader` + `param.weight_loader`，完全同构）。

`self.tp_rank = dist.get_rank()` 在**构造时**求值 —— 意味着 `LinearBase` 子类不能在 `init_process_group` 之前构造。`ModelRunner` 里第 1 步就 `init_process_group`（`docs/07`），第 5 步才建模型，顺序不能换。

## 3. 列并行：切输出

```python
# linear.py:54-73
class ColumnParallelLinear(LinearBase):
    def __init__(self, input_size, output_size, bias=False):
        tp_size = dist.get_world_size()
        super().__init__(input_size, divide(output_size, tp_size), bias, 0)   # ← 输出缩成 1/tp

    def weight_loader(self, param, loaded_weight):
        param_data = param.data
        shard_size = param_data.size(self.tp_dim)          # 本卡的输出宽度
        start_idx = self.tp_rank * shard_size
        loaded_weight = loaded_weight.narrow(self.tp_dim, start_idx, shard_size)  # 切下自己那段
        param_data.copy_(loaded_weight)

    def forward(self, x):
        return F.linear(x, self.weight, self.bias)          # 无通信
```

`divide()`（`linear.py:7-9`）带 `assert numerator % denominator == 0`，所以**任何不能整除的并行度都会在构造时炸**，而不是跑到一半算错。

## 4. 行并行：切输入，末尾求和

```python
# linear.py:131-156
class RowParallelLinear(LinearBase):
    def __init__(self, input_size, output_size, bias=False):
        tp_size = dist.get_world_size()
        super().__init__(divide(input_size, tp_size), output_size, bias, 1)   # ← 输入缩成 1/tp

    def forward(self, x):
        y = F.linear(x, self.weight, self.bias if self.tp_rank == 0 else None)   # ← 只有 rank0 加 bias
        if self.tp_size > 1:
            dist.all_reduce(y)                                                    # ← 求和
        return y
```

**`bias if self.tp_rank == 0 else None` 是个漂亮的小优化**：如果每张卡都加 bias，`all_reduce` 求和后会得到 `tp_size` 份 bias。只在 rank0 加一次，求和后正好一份。

`all_reduce` 是**阻塞集合通信**，在 forward 里同步执行 —— 这意味着行并行层之间是硬同步点。TP=2 时每层 2 次 `all_reduce`（`o_proj`、`down_proj`），28 层共 56 次。这是 TP 在小 batch 下效率不高的根因（通信量与计算量不匹配），也是为什么 vLLM/SGLang 要做"通信与计算重叠"。nano-vllm 完全不做重叠 —— `docs/15` 会把这个和 DeepInfer 的 ZOS 拿来对比。

## 5. QKV 并行：为什么不能 `chunk`

```python
# linear.py:96-128
class QKVParallelLinear(ColumnParallelLinear):
    def __init__(self, hidden_size, head_size, total_num_heads, total_num_kv_heads=None, bias=False):
        tp_size = dist.get_world_size()
        self.num_heads = divide(total_num_heads, tp_size)
        self.num_kv_heads = divide(total_num_kv_heads, tp_size)
        output_size = (total_num_heads + 2 * total_num_kv_heads) * head_size
        super().__init__(hidden_size, output_size, bias)

    def weight_loader(self, param, loaded_weight, loaded_shard_id: str):
        if loaded_shard_id == "q":
            shard_size = self.num_heads * self.head_size
            shard_offset = 0
        elif loaded_shard_id == "k":
            shard_size = self.num_kv_heads * self.head_size
            shard_offset = self.num_heads * self.head_size
        else:  # "v"
            shard_size = self.num_kv_heads * self.head_size
            shard_offset = self.num_heads * self.head_size + self.num_kv_heads * self.head_size
        param_data = param_data.narrow(self.tp_dim, shard_offset, shard_size)
        loaded_weight = loaded_weight.chunk(self.tp_size, self.tp_dim)[self.tp_rank]
        param_data.copy_(loaded_weight)
```

Qwen3-0.6B 的 `num_attention_heads=16`、`num_key_value_heads=8`，所以合并后的输出宽度是 `(16 + 2×8) × 128 = 4096`。如果按 `chunk(2)` 均分，rank0 会拿到 `[q0..q7, k0..k3]` 的错位片段 —— **q、k、v 三段的比例不是 1:1:1，必须按段偏移**。

`shard_offset` 的三个分支正好把"q 全宽 → k 半宽 → v 半宽"排好；然后对 `loaded_weight` 做 `chunk(tp_size)[tp_rank]`（按头切）。**注意两次切的对象不同**：`param_data` 是按"段偏移"切，`loaded_weight` 是按"均分"切。这两个动作不对称，是这段代码最容易看错的地方。

`MergedColumnParallelLinear`（`linear.py:76-93`）解决同类问题（`gate_proj`/`up_proj` 合并成 `gate_up_proj`），区别是它的分段是等宽的，用 `sum(self.output_sizes[:shard_id])` 算偏移：

```python
shard_offset = sum(self.output_sizes[:loaded_shard_id]) // self.tp_size
shard_size = self.output_sizes[loaded_shard_id] // self.tp_size
```

## 6. 权重加载：一次遍历，两种路径

```python
# utils/loader.py:12-28
def load_model(model, path):
    packed_modules_mapping = getattr(model, "packed_modules_mapping", {})
    for file in glob(os.path.join(path, "*.safetensors")):
        with safe_open(file, "pt", "cpu") as f:
            for weight_name in f.keys():
                for k in packed_modules_mapping:
                    if k in weight_name:
                        v, shard_id = packed_modules_mapping[k]
                        param_name = weight_name.replace(k, v)
                        param = model.get_parameter(param_name)
                        weight_loader = getattr(param, "weight_loader")
                        weight_loader(param, f.get_tensor(weight_name), shard_id)
                        break
                else:
                    param = model.get_parameter(weight_name)
                    weight_loader = getattr(param, "weight_loader", default_weight_loader)
                    weight_loader(param, f.get_tensor(weight_name))
```

`packed_modules_mapping`（`qwen3.py:187-193`）就是那张"hf 权重名 → 合并后参数名 + 段号"的表：

```python
{
  "q_proj": ("qkv_proj", "q"),
  "k_proj": ("qkv_proj", "k"),
  "v_proj": ("qkv_proj", "v"),
  "gate_proj": ("gate_up_proj", 0),
  "up_proj":   ("gate_up_proj", 1),
}
```

三点：

1. **`for...else` 的 `else` 属于内层 `for k`**：遍历完所有映射都没命中，才走"普通加载"。所以"safetensors 里有 q_proj → 走合并路径；有 embed_tokens → 走普通路径"。
2. **字符串替换而不是结构化解析**：`weight_name.replace("q_proj", "qkv_proj")` 把 `model.layers.0.self_attn.q_proj.weight` 变成 `model.layers.0.self_attn.qkv_proj.weight`。丑陋但够用；风险是层名里出现同名子串。
3. **`f.get_tensor(...)` 是整块读进 CPU**：没有分块流式加载、没有 mmap 直通 GPU。0.6B 模型在 CPU 侧临时占用约 1.2 GB × 2（bf16 一份 + 转换），大模型会爆。

## 7. 词表并行：embedding 与 lm_head

```python
# embed_head.py:34-42
def forward(self, x):
    if self.tp_size > 1:
        mask = (x >= self.vocab_start_idx) & (x < self.vocab_end_idx)   # 属于自己这段词表？
        x = mask * (x - self.vocab_start_idx)
    y = F.embedding(x, self.weight)
    if self.tp_size > 1:
        y = mask.unsqueeze(1) * y                                       # 不属于自己的置零
        dist.all_reduce(y)                                              # 求和得到完整向量
    return y
```

**`mask * x` 是"查表 + 掩码 + 求和"的经典写法**：不自己的 token 被置零，`all_reduce` 后只有一份非零。

`ParallelLMHead` 是反方向：

```python
# embed_head.py:56-66
def forward(self, x):
    context = get_context()
    if context.is_prefill:
        last_indices = context.cu_seqlens_q[1:] - 1     # ← 每条序列的最后一个位置
        x = x[last_indices].contiguous()
    logits = F.linear(x, self.weight)
    if self.tp_size > 1:
        all_logits = [torch.empty_like(logits) for _ in range(self.tp_size)] if self.tp_rank == 0 else None
        dist.gather(logits, all_logits, 0)               # ← 词表分片收拢到 rank0
        logits = torch.cat(all_logits, -1) if self.tp_rank == 0 else None
    return logits
```

**prefill 时只算每条序列最后一位的 logits**：这是 `docs/02` 说的"prefill 那一步就出第一个 token"的实现基础。若不这么做，一个 4096 token 的 prompt 要算 4096 × 151936 的 logits 矩阵（几个 GB），而现在只要 1 × 151936。

## 8. 数据流总图（TP=2）

```
                x [N, 1024]
                     │
      ┌──────────────┴──────────────┐
      ▼                             ▼
 qkv_proj(rank0)               qkv_proj(rank1)
 [1024×(16+2×8)/2×128]        同名，不同分片
      │                             │
  q/k/v 各一半头                  另一半头
      │                             │
   attention（本地头，读本地 KV 页） ← KV 也是按头切的（docs/08）
      │                             │
 o_proj(rank0, 行并行)          o_proj(rank1)
      └────────── all_reduce ───────┘
                     │
              x [N, 1024] 完整
                     │
      ┌──────────────┴──────────────┐
 gate_up_proj(列并行)          gate_up_proj(列并行)
      └────────── silu*mul ─────────┘
                     │
      ┌──────────────┴──────────────┐
 down_proj(行并行)              down_proj(行并行)
      └────────── all_reduce ───────┘
                     │
                 logits（只 rank0 有完整词表）
```

## 9. 陷阱清单

1. **`dist.get_rank()` 在构造时取**：模块必须在进程组初始化之后创建。
2. **`divide()` 的整除断言**：`hidden_size=1024` 可以被 2/4/8 整除，换模型（比如 hidden=3584）要重新算并行度。
3. **行并行的 bias 只在 rank0 加**：自定义层时若照抄 `F.linear(x, w, b)` 会造成 bias 被放大 tp_size 倍。
4. **`weight_loader` 的签名不统一**：`RowParallelLinear`/`ColumnParallelLinear` 是 `(param, weight)`，`QKV`/`Merged` 多一个 `shard_id`。`loader.py` 靠 `packed_modules_mapping` 区分，漏配就会 TypeError。
5. **`replace` 字符串替换**：层名里若含 `q_proj` 之类的子串会被误替换。
6. **`tie_word_embeddings`**（`qwen3.py:202-203`）：`lm_head.weight.data = embed.weight.data` 让两者共享存储，所以**合并加载时只加载 `embed_tokens.weight`**，safetensors 里的 `lm_head.weight` 若有会被覆盖成同一份 —— Qwen3-0.6B 是 tied，所以实际不存在这个文件。
